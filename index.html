Phase 01 — The Opportunity Model

One contact, many opportunities

One person, many programs — modelled as one contact with many opportunities. The integration must preserve this end-to-end.

One person = one phone = one chat. How do many opportunities share it?

Model A · Keep it in one chat

One shared number carries every program. All opportunities sit in one thread; the CRM tags each message to the right opportunity and names one chat owner.

+ one relationship+ easy to compare+ fewer numbers
− match reply to opp− one chat, many owners

Model B · Named sub-accounts under one verified brand

Verify a parent brand once — HeroVired HeroEducation FMC (when documents are ready) — then run many numbers under it with prefix / suffix name variations. Each LC or function gets its own named number on the same trusted brand.

+ verify the brand once+ prefix / suffix per LC or function+ no per-name approval fight
− more numbers to run− keep one student to one number
Decision — hybrid, with the CRM as the unifier

Default to Model A — one shared number, opportunities separated by tag. Add Model B sub-accounts (named numbers under a verified brand) where a function or senior LC benefits from its own line. Either way the CRM is the unifier — it owns the contact, the active program, and caps consent / frequency per student across numbers.

Phase 04 — Voice + WhatsApp

Voice and WhatsApp, one source of truth

The in-house voice bot is a peer to the WhatsApp bot. CRM conducts; both channels hand off to each other.

How the handoffs work

Two directions, both fired and logged by the CRM: Voice → WhatsApp when a call can't close it, WhatsApp → Voice when a chat needs a human. Each row below reads trigger → what fires.

One opportunity, both channels

One journey across three lanes — Voice, WhatsApp, CRM.

Unified scoring & cost-aware routing

Both channels feed one score; route by heat, WhatsApp-first.

⇄ Integration contract — in-house voice bot

CRM/DoubleTick → Voice  start call — phone, program/university id, stage, latest chat summary.

Voice → CRM  call outcome — transcript, summary, sentiment, disposition, next action.

CRM → DoubleTick  trigger flow — on outcome (missed, asset-requested), fire the WhatsApp message.

Open item — unify consent across channels

Voice (DND, calling hours) and WhatsApp (opt-in, 24h window) must resolve to one consent state per contact.
